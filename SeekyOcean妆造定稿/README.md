# SeekyOcean 双人换装与动画实现说明

## 1. 项目目标

基于本目录的六套静态定稿图，制作一个浏览器端的 SeekyOcean 双人互动页面，首期能力包括：

- 六套固定双人造型切换；
- Ocean 与 Seeky 的丰富表情；
- 待机反应和少量指定动作；
- 使用“同步跳一下”完成换装过渡。

Seeky 和 Ocean 在产品中被视为一个不可拆分的双人组合：始终同时出现，固定左 Ocean、右 Seeky，不提供单人模式。单人图可以用于内部加工，但不能成为最终展示状态。

## 2. 技术范围与技术栈

首期只实现网页，不制作桌面版。

推荐技术栈：

- **Vite + TypeScript**：项目构建和业务代码；
- **PixiJS**：分层渲染、纹理图集、逐帧动画和特效；
- **JSON 资源清单**：声明造型、表情、动作、锚点和播放参数；
- **PNG 透明素材 + 纹理图集**：保留画面质量并减少运行时请求数量。

界面控件可以先使用普通 HTML/CSS，不必在首期额外引入大型 UI 框架。

## 3. 运行时结构

```text
SeekyOceanPair
├─ OceanActor
│  ├─ BodyLayer
│  ├─ HeadLayer
│  ├─ FaceLayer
│  └─ EffectLayer
├─ SeekyActor
│  ├─ BodyLayer
│  ├─ HeadLayer
│  ├─ FaceLayer
│  └─ EffectLayer
└─ PairActionController
```

内部将两人分别分层，便于表现不同表情和动作；`SeekyOceanPair` 必须同时创建和渲染两位角色，外部接口不提供隐藏单人的能力。

每个人物首期只拆成“身体、头部、表情、特效”四类图层，不重新制作完整的手臂、腿和衣袖骨骼系统。

## 4. 素材预处理

当前定稿 PNG 是白底 RGB 图片，没有透明通道。应用开发前应从副本生成透明背景素材，原始定稿文件保持不动。

- 只删除与画布边缘连通的背景区域，避免误删白衬衫、白裤子和鞋子；
- 重点检查簪花细枝、兔耳、头发边缘、白色鞋底和浅色衣物；
- 保持原始像素尺寸，不进行有损缩放或插值；
- 所有动画帧使用固定画布、固定人物中线和固定地面线；
- 纹理打包时可以裁切透明边缘，但清单中必须保留原始锚点和偏移量，防止播放时抖动。

建议资源结构：

```text
public/assets/
├─ manifest.json
├─ outfits/
│  ├─ 01/
│  ├─ 02/
│  └─ ...
├─ faces/
│  ├─ ocean/
│  └─ seeky/
├─ actions/
└─ effects/
```

## 5. 换装系统

换装状态只保存一个双人共用的 `outfitId`：

```ts
type OutfitId = "01" | "02" | "03" | "04" | "05" | "06";

interface PairState {
  outfitId: OutfitId;
  oceanExpression: ExpressionId;
  seekyExpression: ExpressionId;
  actionId: ActionId | null;
}
```

调用一次换装，同时更新 Ocean 和 Seeky 的身体及对应固定头部造型。不允许分别设置两人的服装编号。

### 跳一下换装流程

```text
Idle
  → TakeOff（当前造型同步起跳）
  → Switch（接近最高点时同时替换两人的造型纹理）
  → Landing（目标造型同步落下）
  → Settle（轻微压缩/回弹）
  → Idle
```

实现建议：

- 跳跃使用程序控制的纵向位移和缓动，不为每套衣服重画跳跃帧；
- 两人可以有很小的高度或时间差来增加自然感，但造型切换必须发生在同一时刻；
- 切换点放在最高点附近，此时纵向速度最低，视觉跳变最不明显；
- 可在切换瞬间叠加短促的星光、像素闪光或烟雾特效；
- 动画期间锁定新的换装请求，或只保留最后一次请求，避免连续点击造成状态错乱；
- 落地后必须回到各自原始位置，并重新对齐统一地面线。

## 6. 表情系统

表情不重复绘制整个人物，而是使用可复用的脸部图层：

```text
眉毛 / 眼睛 / 嘴巴 / 腮红 / 表情特效
```

建议首批表情包括：默认、微笑、开心闭眼、大笑、害羞、惊讶、委屈、生气或鼓脸、困倦、哭泣。

Ocean 和 Seeky 可以显示不同表情，但必须同时出现。眨眼和嘴部开合可以使用 3～4 张局部小帧，不需要生成整身动画。

### Seeky 嘴唇约束

Seeky 的嘴唇不是通用像素嘴，而是固定的**心形薄唇**：有轻微丘比特弓，颜色为珊瑚粉。所有表情都应从这一结构演变。

- 微笑时保留唇峰，只抬高嘴角；
- 大笑或惊讶时可以张嘴，但上唇仍应保留心形趋势；
- 委屈或生气时可以改变弧度，不能变成厚重的圆形嘴；
- 不复用 Ocean 的嘴部素材；
- 表情审核时应单独检查嘴唇形状和颜色是否仍能识别为 Seeky。

## 7. 动画实现策略

采用“程序动画 + 局部逐帧 + 完整动作逐帧”的混合方式。

### 程序动画

适用于不改变衣服和肢体轮廓的动作，可跨六套造型复用：

- 呼吸、轻微摇晃；
- 跳跃和落地回弹；
- 两人靠近；
- 头部轻歪或点头；
- 点击反馈和换装特效。

### 局部逐帧

适用于眨眼、说话嘴型、流泪、汗滴、爱心等局部变化，只播放脸部或特效的小范围帧。

### 完整动作逐帧

适用于会改变手臂、身体轮廓、衣袖形状或人物遮挡关系的动作：

- 挥手、比心、敬礼；
- 牵手、拥抱；
- 举起或递交道具。

普通独立反应可以分别制作两人的帧并由控制器同步播放。牵手、拥抱等发生接触的动作应直接按双人组合画面制作，明确前后遮挡关系。

建议帧数和播放速度：

- 眨眼：3～4 帧；
- 挥手：5～8 帧；
- 比心：6～10 帧；
- 拥抱：8～12 帧；
- 角色动作通常使用 8～12 FPS。

所有完整动作先在 **04 背带裤造型**上验证，再决定是否适配其余五套，避免在动作设计尚未确定时产生大量重复绘制。

选择 04 而不是 01 作为动作模板的原因：

- 背带裤造型的身体和四肢轮廓更清楚；
- 01 粉色外套和短裤相对宽松，容易掩盖躯干与肢体的真实运动趋势；
- 04 更适合确定抬手、弯腰、靠近和双人接触时的动作幅度；
- 04 的动作通过后，再根据各套衣服的肩膀、袖长和廓形逐套重绘，不能把 04 的手臂帧直接覆盖到其他服装上。

这里的“动作模板”只用于动画设计，不改变 `设计要点.md` 中 01 粉色装作为既有身体统一规则来源的事实。

## 8. 状态机与冲突处理

```text
Idle
├─ ChangingOutfit
├─ PlayingAction
└─ Reacting
```

- `ChangingOutfit` 期间不能同时播放完整动作；
- `PlayingAction` 期间是否允许眨眼和表情变化，由动作配置决定；
- 动作结束后恢复到对应造型的待机状态；
- 双人接触动作由同一个时间轴驱动，不能由两个独立计时器分别播放；
- 浏览器切到后台后应暂停时间轴，恢复时继续或安全回到待机状态，避免两人动画失步。

## 9. 建议实施顺序

1. 生成透明素材副本并建立 `manifest.json`；
2. 完成双人固定渲染和六套造型加载；
3. 实现“同步跳一下换装”；
4. 制作无五官头部底图和首批表情图层；
5. 实现眨眼、表情切换及待机程序动画；
6. 使用 04 背带裤造型完成第一个完整逐帧动作；
7. 确认动作效果后，再扩展其他造型和双人接触动作；
8. 完成加载优化、移动端适配和最终视觉检查。

## 10. 尚待确认

- 首批表情的最终清单及两人的性格差异；
- 首批需要绘制的具体动作；
- 页面背景、按钮和整体视觉风格；
- 是否需要声音、台词气泡或点击互动；
- 动作是否必须覆盖全部六套造型，还是允许部分动作只属于特定造型。

角色视觉定稿以 `设计要点.md` 为准；本文件只定义应用实现方式和素材生产规范。
